## Phase Goal

**As a** Linux desktop user, **I want to** click a function orb to spawn or focus the timestamp window, convert Unix time both ways, and copy results through the shared chrome, **so that** I can convert and copy times from one independent tool window without a second copy.

This plan is Slice 1 of that goal (LAUNCH-01, LAUNCH-02, UI-02 chrome shell). After it lands, the clock orb opens or focuses `xtools-time`. Live convert and copy are Plan 02-02.

## Artifacts this phase produces

- Workspace member `crates/xtools-time` (eframe 0.36.1 tool; host stays GTK)
- `xtools-ui` `egui-chrome` feature with `apply_theme`, title strip, labeled field, copy control, now control, inline error
- `TIME_INSTANCE`, `ToolId::binary_name`, `ToolId::instance_name`, `raise_instance`
- Host clock-orb path: mint token from stashed `gdk::Event` → connect raise first → spawn sibling only if absent
- Independent decorated timestamp window, title `xtools · 时间戳`, 560×480 centered, skip-taskbar, filled from now
- Close quits the timestamp process; next clock click is a new now-filled process

## Prohibitions

- Do not add a second windowing toolkit to `xtools-host` (D-01). Host must not enable `egui-chrome`.
- Do not make the timestamp window Overlay, layer-shell, or always-on-top (D-01).
- Do not search `$PATH` for the tool binary. Do not `env_clear` on spawn.
- Do not spawn when the raise socket connect succeeds. A missed Focus is not a license for a second window (D-03, LAUNCH-02).
- Do not spawn JSON or translate binaries. Those orbs still only collapse the menu.
- Do not create `xtools-json` or `xtools-trans` crates.
- Do not ship extra copy targets or a custom format box (D-12, D-13). Plan 02-02 owns copy behavior.
- Do not persist last values or last window position.
- Do not use `wmctrl`, `_NET_ACTIVE_WINDOW`, or the stale single-instance crate.
- Do not log pointer coordinates or the activation token at info/warn.
- Do not run formatters, clippy, or a test suite.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Compositor pointer → host mint_token | Untrusted gdk::Event time/surface used to request an activation token |
| Host → sibling xtools-time | Exec of a same-directory binary plus inherited env and one token var |
| Abstract RAISE socket → live TimeApp | Local peer can write a RAISE line; token is not a secret |
| Tool process → compositor | Focus and first-map activation |

No client↔network boundary exists in this plan. Do not add one.
