## Phase Goal

**As a** Linux desktop user, **I want to** drag an always-on-top main orb and click it to expand or collapse three compile-time function orbs painted from shared theme tokens, **so that** I can park a quiet x on the output and open the timestamp / JSON / translate menu without a query field.

This plan is Slice A of that goal (HOST-01, UI-01): after it lands, `cargo run -p xtools-host` shows a draggable Overlay orb on this KDE Wayland session. Expand/collapse is Plan 01-02.

## Artifacts this phase produces

- Virtual Cargo workspace (`resolver = "3"`, `default-members = ["crates/xtools-host"]`)
- `crates/xtools-ui` token + `ToolId` library (no GUI toolkit)
- `crates/xtools-host` GTK4 + gtk4-layer-shell Overlay binary
- Runnable always-on-top 40 logical-px dark disk with a light **x**, mid-right, draggable, clamped
- Collapsed scanline input region (main disk only)
- `SKELETON.md` architectural contract (already emitted beside this plan)

Plan 01-02 then adds the three-ball fan, 120 ms pop, two-state input region, dismiss paths, and pointer-event stash.

## Prohibitions

- No query field / command palette
- No plugin directory and no directory scan for tools
- No egui/winit host toolkit in `xtools-host` (D-01; AGENTS.md STACK host chapter is overruled)
- No tool windows, no `Command::new` of a tool binary
- No persisted orb position (D-18); restart returns to D-16
- Do not copy the official layer-shell sample's Top layer or automatic exclusive zone
- Do not create `xtools-time`, `xtools-json`, or `xtools-trans` crates
- Do not add HTTP, D-Bus exports, or a database
